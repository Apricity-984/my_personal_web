# 技术成长路线

从「会一点」到「能交付」，把学习变成一条看得见的路。

这份路线图围绕一个简单原则展开：**每学一段，就做出一个能被使用、被展示的东西。**不必按周赶进度，也不必一次学完所有分支；先走到下一个路标，再根据兴趣调整方向。

## 01 · 打好地基 { #01-foundation }

<div class="roadmap-stage stage-foundation" markdown="1">

<div class="stage-heading"><span class="stage-number">01</span><div><span class="stage-label">FOUNDATION</span><h3>先让工具听你的</h3></div><span class="stage-time">按需补齐</span></div>

这一阶段建立稳定的开发习惯。熟悉文件、终端、浏览器开发者工具和 Git；理解变量、条件、循环、函数这些通用概念。先不追求把原理背熟，重点是知道遇到问题时如何拆解、搜索和验证。

**练习项目**　用 Markdown 写一份自己的学习主页，放上简介、正在学的内容和常用链接，再用 Git 保存每次修改。

**完成标志**　能独立创建仓库、提交改动、读懂常见报错，并能说清楚一次修改是怎么从本地进入版本历史的。

</div>

## 02 · 构建 Web { #02-web }

<div class="roadmap-stage stage-web" markdown="1">

<div class="stage-heading"><span class="stage-number">02</span><div><span class="stage-label">THE WEB</span><h3>把想法变成页面</h3></div><span class="stage-time">边做边学</span></div>

按 **HTML → CSS → JavaScript** 的顺序学习。先把内容结构写对，再处理布局、颜色和响应式，最后加入交互。练习时多用浏览器检查元素，观察页面在手机和电脑上的变化。

**练习项目**　做一个个人主页或读书清单：能新增条目、标记状态、筛选内容，并适配窄屏阅读。

**完成标志**　从空白文件开始做出一页完整、自适应的界面；能用自己的话解释结构、样式和交互分别由什么负责。

</div>

## 03 · 写出可靠的应用 { #03-engineering }

<div class="roadmap-stage stage-engineering" markdown="1">

<div class="stage-heading"><span class="stage-number">03</span><div><span class="stage-label">ENGINEERING</span><h3>从页面走向应用</h3></div><span class="stage-time">选择一条主线</span></div>

当页面开始包含多个功能，再学习组件化和一个前端框架（例如 Vue 或 React）；理解状态、路由、接口请求和错误处理。补上 HTTP、JSON、浏览器存储等 Web 基础。需要保存多人共享的数据时，再进入后端、数据库与身份验证。

**练习项目**　把前一阶段的小作品升级成一个有分类、搜索和持久化数据的应用；把加载中、空数据和失败情况也设计完整。

**完成标志**　能拆分功能和组件，能读懂一次接口请求从发起到显示的过程，并能定位常见的状态或数据问题。

</div>

## 04 · 发布并持续迭代 { #04-ship }

<div class="roadmap-stage stage-ship" markdown="1">

<div class="stage-heading"><span class="stage-number">04</span><div><span class="stage-label">SHIP & GROW</span><h3>让作品真正上线</h3></div><span class="stage-time">持续循环</span></div>

学习构建与部署，把项目发布到可访问的地址。写清楚 README、截图和使用方式；请别人试用，记录反馈，再做一轮改进。接下来根据目标选择深化方向：前端体验、后端服务、数据分析、自动化或开源协作。

**练习项目**　发布一个你自己也会继续使用的小工具，并为它写一篇复盘：解决了什么问题、遇到了什么、下一步要改什么。

**完成标志**　别人能打开并理解你的作品；你能从反馈中挑出一个具体问题，完成修改，再把新版本发布出去。

</div>

## 之后，按兴趣分支

主线走通后，不需要把所有技术都学一遍。挑一个让你愿意长期投入的方向，围绕真实问题做更深入的项目：

<div class="roadmap-branches" markdown="1">

<div><span class="branch-icon">◒</span><strong>前端体验</strong><p>设计系统、无障碍、性能优化、复杂交互</p></div>
<div><span class="branch-icon">⌘</span><strong>后端与系统</strong><p>API 设计、数据库、缓存、可观测性</p></div>
<div><span class="branch-icon">▤</span><strong>数据与自动化</strong><p>数据处理、脚本工具、工作流与 AI 应用</p></div>
<div><span class="branch-icon">✳</span><strong>协作与开源</strong><p>代码评审、文档、社区协作、长期维护</p></div>

</div>
